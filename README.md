# CipherShield AI

**A local-first secret-isolating AI gateway for LLM-powered security analysis.**

CipherShield AI lets an analyst submit an incident report, log excerpt, or
API trace for AI analysis while keeping raw secrets and vault keys outside
the external provider boundary. Detected secrets are replaced with opaque
placeholders before a request leaves the trusted backend; the mapping is
kept in a local AES-256-GCM vault and restored only through an explicit,
authorized, audited action.

> **Claim scope:** we say *local-first secret-isolating gateway*, not
> "zero knowledge". Regex detection is incomplete by design and is not a
> universal DLP solution. See [`security/threat-model.md`](security/threat-model.md)
> for what this system does **not** protect against.

## Problem

Security teams send logs and incident reports to LLM assistants. The raw
text routinely contains API tokens, passwords, IPs, and emails — and it
leaves the machine in plaintext form.

## Solution

```
raw text → detect → tokenize → encrypt mapping → policy gate → LLM (placeholders only)
                                   ^                             |
                                   vault (AES-256-GCM)     response scan → sanitized output
```

- Secrets are detected and replaced with `[SECRET_01]`-style placeholders.
- The policy gate re-scans the **exact serialized** outbound body and fails
  closed.
- The master/vault key and provider API key never leave the backend.
- Model output is scanned for known-secret disclosure before display.
- External calls are **disabled by default** (`ALLOW_EXTERNAL_LLM=false`).

## Setup (clean clone, no API key needed)

```bash
# Backend
cd services/api
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
cp ../../.env.example ../../.env     # mock mode by default
uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000

# Frontend (second terminal)
cd apps/web
npm install
npm run dev                          # http://localhost:3000
```

Or with Docker:

```bash
docker compose up --build
# UI  http://localhost:3000
# API http://localhost:8000/health
```

Single container instead (API + UI together — repo-root `Dockerfile`,
same-origin: the browser only needs ONE port):

```bash
docker build -t ciphershield .
docker run --rm -p 3000:3000 ciphershield
# http://localhost:3000  (UI; /health and /api/* proxy to the bundled API)
```

**Deploy to Render:** push to GitHub, then Render → *New → Blueprint* → select
the repo — the included `render.yaml` provisions both services (you are
prompted for three values). Full walkthrough, env reference, and caveats:
[`docs/deploy-render.md`](docs/deploy-render.md).

Open <http://localhost:3000> — the Analyze screen works fully in mock mode.

### Enabling a real OpenAI-compatible provider

```dotenv
ALLOW_EXTERNAL_LLM=true
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_API_KEY=sk-...        # stays server-side; never returned by any API
```

## Tests

```bash
cd services/api && pytest -q         # unit + integration + adversarial (offline)
ruff check . && ruff format --check . && mypy app
cd apps/web && npm run lint && npm run typecheck && npm test && npm run build

# Metrics produced from real runs (writes eval/results/summary.json + report.md)
python scripts/run_security_eval.py
```

The evaluation report is rendered live on **Audit & Evaluation** — every number
comes from `eval/results/summary.json`, generated by the runner (baseline vs
gateway comparison, leakage, blocked requests, attack success rate, false
positives, utility, latency, provider-call counts, suite results).

## Security limitations (read before trusting it)

- Detection is pattern-based: unknown secret formats can leak.
- Protection assumes an uncompromised backend host.
- The external provider sees everything that passes the gate, per its terms.
- The audit hash chain is tamper-*evident*, not rewrite-proof against an
  administrator with the whole log.
- Tests demonstrate behavior on the synthetic corpus only — no formal
  verification is claimed.

See [`security/threat-model.md`](security/threat-model.md),
[`security/security-invariants.md`](security/security-invariants.md), and
[`docs/demo-script.md`](docs/demo-script.md).
